# パフォーマンス

## 1 フレームのコスト

1 フレームあたり、プレイヤー 1 つにつき、**JavaScript が行う呼び出しは 1 回**です（`drawInto`）。時間を進めること、ジオメトリを組み立てること、Skia の描画呼び出しを発行することは、すべてその下 — Rust コアとその隣の C++ — で行われ、頂点が JSI 境界を越えることはありません。

ここから 2 つのことが導かれます。設計時に意識する価値があります。

- **JS 側のコストは、画面上のプレイヤーの「数」に比例し、その複雑さには比例しません。**
  300 パーツのキャラクターと 3 パーツのロゴは、JS スレッドにとって同じコストです。
- **描画のコストはピクセル数に比例します。** エフェクトやパーティクルのパーツは、大きくほとんど透明な四角形を何枚も重ねるので、同じピクセルが何度も塗られます。サーフェスの大きさはビューのサイズ × デバイスのピクセル比で、この 2 つを切り離す手段はここにはありません — ビューが小さければ、それだけ仕事が減ります。

::: warning このページの背後に実機の数値はありません
実機での計測はまだ行われていません。iOS シミュレータと Android エミュレータのみで、しかもホストの CPU は、実機が苦しむまさにその側面を実際より良く見せます。ベンチマークではなくコストモデルとして読んでください。計測するときは **release** ビルドで行ってください。debug バンドルは、ここに書かれたすべてを覆い隠します。
:::

## たくさんのアニメーション: ビューを並べずシーンを使う

`<SpriteStudioView>` はキャンバスとフレームループを 1 つずつ持ちます。ビュー 20 個はキャンバス 20 枚とクロック 20 本で、これが上の規則では救えない唯一の配置です。
`<SpriteStudioScene>` は**キャンバス 1 枚・クロック 1 本**で登場人物全員を描き、スプライト自身は何も描画しません。[たくさんのアニメーション: シーン](/ja/usage/scene)を参照してください。アプリがバックグラウンドに回ったときに繋ぐとよい `paused` もそこにあります。

## フレームループを増やす唯一の API

`useSsPartTransform` だけは、ここまでの話の例外です。`<SpriteStudioPartAnchor>` も 1 つずつがこのフックです。このフックはインスタンスごとに**ビューのものとは別の `requestAnimationFrame` を起こし**、`getPartTransform(partName)`
経由で読み出します — フレームごとに、パーツごとに、文字列が JSI 境界を越えます。設計の他の部分が取り除いたはずの「毎フレームの JS 処理」を、唯一再導入している公開 API です。

キャラクターの頭上に体力バーを 1 つ固定するには、妥当な対価です。パーツ 20 個には妥当ではありません。2 度目に手を伸ばす前に知っておく価値があります。[パーツのオーバーライドと追従](/ja/usage/parts)を参照してください。

## 待ち時間の正体は読み込み

`.ssab` のパースは安く、JS ヒープに入らないバイト列に対して C++ で行われます。**アトラスのデコードはそうではありません** — テクスチャは 1 枚ずつ PNG デコードで、こちらが遅い方の半分です。キャッシュが冷えた状態でマウントされたビューは、その間 `placeholder` を表示します。

- **画面遷移の前にキャッシュを温めておく** — `ssPreload`。[プリロード](/ja/usage/textures#preloading)。
- **レジストリをプレイヤー間で共有する。** 同じセルマップを 2 度デコードせずに、複数のプレイヤーが 1 組のアトラスから描けます。[テクスチャとリソース](/ja/usage/textures)。
- **Embedded パックのコストを忘れない。** エンコードされたバイト列は、デコード済みテクスチャとは別に、リソースの生存期間中ずっと常駐します。Reference パックはテクスチャごとに 1 ファイルを持ち、同じセルマップを名指しするパック間で共有します。
  [Reference パックと Embedded パック](/ja/setup/assets#reference-and-embedded-packs)。

## box の計測もタダではありません

既定の作者のキャンバスに収める分にはコストは掛かりません。代わりにボックスを計測する（`frameScope`）と、アニメーションを 1 フレームずつベイクしながら走査し、`'pack'` ではその走査をアニメーション 1 本ごとに払います。どちらも[基本の再生](/ja/usage/basic)にあります。
