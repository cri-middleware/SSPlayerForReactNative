# どこから見るか

[生成リファレンス](/api/)にはすべてが載っています。このページは、そのうちどれが必要かを、
およそ必要になる順に示します。

## 実際に使う 4 つ

| | |
|---|---|
| [`SpriteStudioView`](/api/) | アニメーション 1 つ、自前のキャンバスとフレームループ。既定の選択肢です。 |
| [`SpriteStudioScene`](/api/) + `SpriteStudioSprite` | 複数のアニメーション、キャンバス 1 枚とクロック 1 つ。 |
| `SsPlayerProps` | *どのアニメーションをどう再生するか*のすべて。両コンポーネントで共有されるので、両者がずれることはありません。 |
| `SsPlacement` | *どこに描画するか*のすべて — `fit`・`align`・`frame`・`offset`・`scale`。 |

## プレイヤー自体が必要になったら

`SpriteStudioPlayer` は描画バックエンドを持たないトランスポートです。ref
（`ref.current.player`）から到達して、シーク、アニメーションの切り替え、コンテンツ
ボックスの読み取りを命令的に行えます。これが interface として規定されているのは意図的で、
react-native-web のルートが同じ API を別の実装から提供できるようにするためです。

## 事前に読み込む

`ssPreload(source)` は使い捨てのプレイヤーを読み込むことでリソースとアトラスのキャッシュを
温めるので、温まったキャッシュに対してマウントされたビューは最初のフレームから描画されます。
`ssUnload(source)` はそれを返却し、`ssClearCaches()` はすべてを破棄します。

## 診断

- `ssCheckForLeaks(source)` — N 回ロードと破棄を行い、ネイティブハンドルのカウントが
  戻ったかを報告します。達成条件を実行可能にしたものです。
- `SsRuntime.liveHandles` — カウントそのもの。
- `player.lastTextureReport` — 直近のロードで解決できなかったもの。テクスチャの欠落は
  そうでなければ無言です。バッチがスキップされるため、症状は「あるパーツが単に
  存在しない」ことになります。

## テクスチャ

`SsTextureRegistry` は、セルマップ名のハッシュを、そのバッチが描画に使うペイントへ
対応づけます。パックは自身のものを読み込むので普段触ることはありませんが、これを渡すと
複数のプレイヤーでアトラスを共有でき、`register(name, image)` で実行時にテクスチャを
差し替えられます。
