# SpriteStudio Player for React Native — Roadmap

This file lists **unfinished work only**: a finished item is deleted, technical constraints live in [docs/limitations.md](docs/limitations.md), and work that waits on the SDK is also tracked in the [SDK ROADMAP](https://github.com/cri-middleware/SpriteStudio-SDK/blob/HEAD/ROADMAP.md).

[CONTRIBUTING.md](CONTRIBUTING.md) is the working guide and [README.md](README.md) carries the requirements.

## Playback & rendering

- [ ] **Animation blending / crossfade** — Layer and cross-fade animations on one player through the SDK's track stack — `ss_runtime_set_track_animation`, `ss_runtime_crossfade`, `ss_runtime_add_track_source`, `ss_runtime_fade_track` and the rest of the track calls. The SDK side is complete; it is **not bound in Nitro or TypeScript yet**: `SsRuntime.nitro.ts` and `SpriteStudioPlayer` expose no track or crossfade call. SSPlayerForWgpu surfaces it (`set_track_animation` / `crossfade` / `fade_track`), and the names follow the SDK's Player API Conventions (§3-2): `setTrackAnimation`, `crossfade`, `addTrackSource`, `fadeTrack`. Motion blending is the selling point; it follows the first release rather than gating it.
- [ ] **`Nines` and `Text`** — The two draw kinds this Player does not draw, and no sibling Player draws either, so there is no reference port to read. **Nines** shares Shape's box-coordinate idea but needs its own buffers. **Text** is a Player responsibility: glyphs need host resources the Brain does not own — an outline font is named by family only and never ships in the `.ssab`, a bitmap font does ship (`FontBitmap` / `FontGlyphBitmap`) and leaves layout. The Brain still emits a geometry-less `Text` batch per text part so the part keeps its place in priority order, which is what a Player composites against; text authored as a mask is dropped from the plan, having no glyphs to write coverage with.
- [ ] **Masked Effect** — An effect draws unmasked: the mask replay places its coverage sample per fragment by inverting one affine quad's UV, and an effect is a cloud of particle quads with no single shape to cut. Masked Mesh and masked Shape are handled — a Shape writes the coverage UV into its spare texcoord channel, a Mesh is drawn into an isolated layer that the coverage cuts with `kDstIn`. SSPlayerForWeb clips a masked Effect in both of its renderers.
- [ ] **The `ss-*` integration shaders, read in composition** — All thirteen have bodies. `pnpm run check-shader` compiles each one, checks that the uniforms line up, checks each shader against its neutral and characteristic case and `ss-sepia` against the SpriteStudio reference to 1/255, and the example's `Shader` card shows every effect applied — but each of those draws a flat quad through a single shader. What none of it establishes is fidelity in composition: the effect with the atlas's real UVs, a PartColor riding along and a blend mode underneath, where several effects would look plausible while being subtly wrong. The neighbour-samplers are where the gap is widest: `ss-blur`, `ss-outline`, `ss-move` and `ss-scatter` step by texels, so a part whose cell is packed tight against its neighbours in the atlas pulls in whatever is next to it. SpriteStudio and the other ports share that property, so matching them may mean matching it too — read it on a screen before deciding it is a bug. The `Shader` pack's own listing (28 parts, all 13 ids) comes out of the bake plan, which says what the pack asks for, not what drew.
- [ ] **`useSsPartTransform` runs its own frame loop, one per part** — and every `<SpriteStudioPartAnchor>` is one of it. Each hook instance starts a second `requestAnimationFrame` beside the view's, and every frame it resolves the part name with `findPartIndex` across JSI before reading the transform by index — per part, on the JS thread. It is the one consumer-facing API that reintroduces the per-frame JS work the rest of the design removes. The by-index read already exists (`SpriteStudioPlayer.getPartTransform` takes a name or an index), so the hook can resolve the index once per animation; publishing from the draw the view already runs would remove the second loop as well, and is the form that composes with the Reanimated tick below.
- [ ] **Reanimated tick** — Part transforms already publish as a SharedValue (`useSsPartTransform`), the consumer-facing half, which does not change when the tick moves. **What is left is the tick itself**: it is still `requestAnimationFrame` on the JS thread. `useFrameCallback` needs the whole update → bake → draw chain reachable from a worklet runtime, and the borrow rule says update and draw cannot land on different threads, so it is one move rather than an incremental one. SharedValue *inputs* — frame, speed, blend weight — are not bound either; the blend inputs would drive the track calls named in the animation blending item above.

## UI integration

A `<SpriteStudioView>` is a real native view, so Yoga lays it out and `fit` / `align` place the animation in its box. What is missing is everything past placement — the parts of a control the view does not implement. `Nines` and `Text` above are the drawing half of the same story.

- [ ] **Per-part hit testing** — The view answers pointers as a rectangle, so an irregular button eats every tap inside its bounding box and a transparent margin swallows whatever is behind it. Two pieces, in order: a **part rect read-out** built from the `PartState` fields the runtime already delivers every frame (`size_x` / `size_y`, `anchor`, `pivot`) plus the part transform — it belongs beside `getPartTransform`, and reading **by index** avoids repeating that hook's per-frame string marshalling — and then `hitTestPart(x, y)` over it, in view coordinates so the `fit` transform is already applied. The same read-out is what a caller needs to place a `<Pressable>` over one part of an animation.
- [ ] **UI state binding** — `<Pressable>` hands its child a state (`pressed`, and `hovered` / `focused` on the platforms that have them); nothing maps that onto an animation or a label, so every app writes the same `onPressIn` / `onPressOut` glue. A component that takes a state-to-animation map keeps it in one place, and is the only piece of this that is purely JS.

## Distribution & verification

- [ ] **A physical device** — Everything here runs on the iOS simulator and the Android emulator only — no device, on either platform. This is the one thing keeping the basic-playback exit criteria open, and it is also what a re-measure needs: the simulator's host is an Apple Silicon Mac, so the CPU side — the side the JS-marshalling variants are limited by — is flattered relative to a phone. Blocked on: a physical iOS and Android device.
- [ ] **The Nitro glue and the Kotlin are compiled only by a platform build** — The host checks (`tools/check-*.sh`, `tools/check-skia-compile.ps1`) compile `SsBaker`, `SsEffect`, `SsInstance`, `SsMask` and `SsSkiaDraw`; `HybridSs*.cpp`, `SsAssets.cpp`, `SsRNSkiaInterop.cpp`, `SsPlayerJni.cpp` and `android/src` are built only by an iOS or Android build, so a change confined to them is verified by everything except a C++ compiler. A host syntax check is not the way round it: the generated Nitro specs include `<NitroModules/…>`, which resolves through CocoaPods' header map rather than through any include path a host `clang++` can be handed.
- [ ] **macOS** — RN Skia and Nitro both support it, so it may simply work. Not in CI, not guaranteed.
- [ ] **Windows** — neither Nitro nor RN Skia supports react-native-windows, which is a separate C++/WinRT stack. Blocked on: react-native-windows support in Nitro and RN Skia.
- [ ] **The pinned SDK release does not exist yet** — `scripts/SDK_VERSION.txt` names a tag the SpriteStudio-SDK repository has not published, so `pnpm run download-sdk` fails and `pnpm run release` fails with it — that is the correct failure, since there is nothing to publish against. Three things unblock together with it: CONTRIBUTING.md, `docs/development/from-source.md` and `example/README.md` can stop presenting `download-sdk` as the no-Rust path while it cannot work, `download-sdk` can say *why* a 404 is expected rather than printing curl's, and the submodule gitlink can move from a branch commit to the tag. **It gates every publish, prerelease included**, and not only through `release`: `prepack` refuses a tarball whose `native/BUILD_MODE` is not `release`, only `download-sdk` writes that file, and `build-runtime` deletes it on purpose — a local build is not the pinned release, so building the Brain from the submodule is not a way around this one. Blocked on: the SDK publishing the release tag `scripts/SDK_VERSION.txt` names.
- [ ] **What the first published version is called, and what promotes it** — The package is `7.0.0-beta.1` — the SDK tag `scripts/SDK_VERSION.txt` pins, which is the family line — and `publishConfig.tag` is `beta`, so a publish cannot take `latest`. What is open is whether the first release stays a prerelease and what promotes it: the physical-device run and the `browser` entry under npm publishing. react-native-web is not one of those — it adds a platform rather than maturing this one.
- [ ] **npm publishing** — `browser` (the web stub barrel) still points at `src/index.web.ts` rather than into `lib/`, which the field's own `//browser` note in `package.json` records; `main`, `module` and `types` already resolve into `lib/`. The publish itself is gated by the pinned SDK release above: `prepack` refuses a tarball built against anything else.
- [ ] **Bare React Native support** — an app with no Expo config plugin gets neither the asset copy nor the ABI narrowing, so both build steps need documenting by hand and checking. `CMakeLists.txt` already tells "does not ship this slice" apart from "not installed" and names the `-P` escape.
- [ ] **React Native Directory listing** — `ios` and `android` up, in an entry appended to `react-native-libraries.json` (`react-native-community/directory`). The Directory reads the registry for its data, so this **cannot come before npm publishing**. Three things not to get wrong. **`false` values are skipped, never written**, so `web` and `expoGo` are stated by their *absence* — the web filter then excludes this package, which is the correct outcome and not something to work around; the prose belongs in the README, which carries it. **`newArchitecture` takes `'new-arch-only'`**, which is this port exactly — the field is otherwise auto-detected, and a failed detection reports "untested" rather than nothing. And **`alternatives` is not the place to point at SSPlayerForWeb**: it is for a library that is unmaintained or lacks New Architecture support, neither of which this is. (`configPlugin` is auto-detected, and true here.) Blocked on: npm publishing.
- [ ] **A fuller example app** — the example has two screens, Viewer (every pack through `<SpriteStudioView>`) and Part follow (`useSsPartTransform` and `isPartSkinnedMesh`); `<SpriteStudioScene>`, `<SpriteStudioSprite>` and Yoga layout are not demonstrated, and a real showcase is still owed.

## Needs SDK

- [ ] **Stretch a `Nines` part to the layout box** — The runtime evaluates a Nines part's size from its keyframes and hands over finished vertices, and the Override Layer covers colour / cell / visibility only — nothing can resize one from the host, so an authored window frame cannot follow the box Yoga gives it, and scaling the player distorts the border art rather than stretching the middle. Waits for: Per-part size override.
- [ ] **tvOS / visionOS** — blocked on the **Brain**, not on React Native: the SDK's XCFramework has no tvOS or visionOS slices yet. Waits for: tvOS / visionOS XCFramework slices.

## Backlog

- [ ] **Embedded audio bytes** — An `--embedded` pack carries its audio in `embedded_assets` with no sibling on disk, so `filePath` names nothing openable; the event's `embedded` flag keeps that legible rather than presenting as a missing file. The shape it wants is the texture one — a pack-level `getSounds()` read once at load, not an `ArrayBuffer` per event that the next `update()` invalidates.
- [ ] **`SsShaderEffect`'s compile cache is not thread-safe** — Function-local statics with no synchronisation, which is fine while every draw is on the JS thread and stops being fine the moment the tick moves to a worklet runtime. Worth doing *with* that move rather than before it, so the ordering rules are written once.
- [ ] **`pnpm run generate-assets` from the repository root does nothing useful** — It resolves `./assets/ss`, which only exists inside `example/`, so from the root it reports "no directory" and exits. Either point the script at the example or drop it and document the `npx` form.
- [ ] **`tools/check-framedata.sh` dies silently without Homebrew** — With `flatc` installed but no `brew`, `FB_INCLUDE=$(brew --prefix …)` under `set -euo pipefail` and with stderr redirected exits 127 and prints nothing; without `flatc` the script already says what it wanted. It should say so in this case too.
- [ ] **Free an embedded atlas after decoding** — The encoded bytes sit inside the same contiguous FlatBuffer the resource holds for its life, so embedded permanently costs one encoded atlas on top of the decoded texture. Blocked on: an SDK-side way to drop `embedded_assets`, or a converter that emits a stripped companion (neither is in the SDK ROADMAP).
- [ ] **react-native-web** — The stub barrel (`src/index.web.ts`) keeps a mixed web/native app's web bundle building, so what is missing is the drawing, not the build. What a route adds is sharing one component tree between an app's two halves, which is narrower than "SpriteStudio on the web"; SSPlayerForWeb answers that completely, and a web-only ask belongs there. There are **two routes, and the cheaper one is not the better one.** Taking `@spritestudio/ssplayer-webgl` as-is shares **only the L3 API and L4 prop types** and pays forever in keeping two renderers in agreement. Taking `@spritestudio/ssplayer-core` under **CanvasKit** shares **L2–L4 whole**: RN Skia runs on web, so the only layer web lacks is L1, and `ssplayer-core` is renderer-agnostic TypeScript (`GeometryBuilder`, `MaskPlanner`, `MaskComposition`, `PartTransform`) — more to write, but then two L1 implementations draw through one Skia API rather than two unrelated renderers. **Neither route vendors SSPlayerForWeb**: a submodule would hang a second `SpriteStudio-SDK/` gitlink in the tree to drift against the root one, and a vendored copy of a package the consumer may already have is the two-copies problem peer dependencies exist to prevent. What has to match is the SDK ABI, not a git SHA, and an npm range says that. Keeping L2 React-free and L3 an interface leaves the door open. Revisit on a concrete request. Blocked on: `@spritestudio/ssplayer-core` and `@spritestudio/ssplayer-webgl` being published to npm.

## Deliberate non-goals

Each is this port's own decision, **not** "matching the Web / Flutter / Godot ports" — those disagree with each other and with this one.

- **A recursion guard on Instance parts** — An instance part that mounts its own animation recurses until the stack gives out. Left as it is, and the general rule it comes from is worth stating once: **the safety code in this Player is kept to a minimum.** What a Player is for is simplicity and speed, and every defensive branch costs both. Which pack and which animation an app plays is the app's own business; a cyclic reference is a content bug its author can see in the editor. A depth cap decides on that author's behalf where legal nesting should have stopped, and cycle detection is more machinery than the case is worth.
- **Validating what a caller passes to the transport** — `seek(NaN)` reaches `ss_runtime_set_frame_no` unexamined — NaN fails every comparison, so the Brain's clamp passes it through and the frame it produces has no parts in it. One `Number.isFinite` would stop it, and it is left out for the same reason as the recursion guard above: what an app asks the transport to do is the app's own business, and a Player earns its keep by being simple and fast rather than by checking its caller's arithmetic. Recorded because the symptom — everything vanishes — reads as a renderer fault rather than a bad argument.
- **A per-frame callback (`frame_updated`)** — The flagship emits one every tick, but it is a C++ signal inside an engine there and would be a JS-thread callback here — on the one path this design is built around avoiding, for every player on screen, every tick. The per-frame *value* case has a better answer in `useSsPartTransform`; the *reaching a frame* case is what the authored user-data and signal keys are for. Revisit on a concrete case that neither covers.
- **`ss_runtime_reset`** — not needed by this design. It empties a context, and a load here builds a **new** `SsInternalPlayer` whose context is created fresh and disposed with it. It becomes necessary only if a context is ever reused across packs, which would be traded against the exact `liveHandles` accounting the leak check stands on.
- **A bundled converter** — React Native has no editor to host an importer in, so `.sspj` → `.ssab` stays a host-side `ssconverter-cli` step.
- **`map0`/`map1` extra shader textures** — no asset here authors one, and they would need a second and third entry in the per-call texture table.
- **Shader parts on Mesh / Shape / Effect kinds** — the reconstruction wants one affine quad to invert. Masking reaches Mesh and Shape by other routes (a layer cut, a spare texcoord channel), so only Effect is out of both.
